# Vanilla_DQN.py - Vanilla DQN Implementation for MountainCar-v0

A complete standalone implementation of Deep Q-Network (DQN) for the MountainCar-v0 environment, suitable for Q3.1 and Q3.2 requirements.

## Overview

This implementation provides:
- **Q3.1**: Complete vanilla DQN implementation
- **Q3.2**: Return vs episodes plots with confidence intervals
- **Q3.2**: Behavior analysis and visualization
- **Q3.2b**: Video recording for behavior analysis

## Notes
- Eventhough the device displays CUDA as available, the implementation uses CPU for training due to memory constraints.
- The data mentioned in the report is generated by running Vanilla_DQN.py with the --auto flag. The script with this flag will automatically train the model, generate videos, and create plots. If a trained model is already present, it will skip to generating videos and plots, please either delete the existing model (checkpoints folder and *.pth files) or rename it before running the script.

## Features

- **Standalone Implementation**: No external dependencies except standard ML libraries
- **Statistical Analysis**: 15 random seeds with confidence intervals
- **Checkpoint System**: Automatic saving of training progress
- **Video Recording**: Generate MP4 videos of trained agent behavior
- **Fast Mode**: Development mode for quick testing
- **Reproducible Results**: Fixed random seeds and saved data

## Fast Mode (Development)

For quick development and testing, set `FAST_MODE = True` in the script:

- **Episodes**: 1000 instead of 2000
- **Updates**: Every 4 steps instead of 1
- **Checkpoints**: Every 200 episodes instead of 50
- **Device**: CPU instead of GPU
- **Batch size**: 128 instead of 64

Change line 45 in `Vanilla_DQN.py`:
```python
FAST_MODE = True  # For development
```

## Behavior Analysis

The trained agent demonstrates the optimal **valley momentum strategy**:

1. **Phase 1**: Drives LEFT to build potential energy
2. **Phase 2**: Uses gravity to accelerate through valley
3. **Phase 3**: Momentum carries car up RIGHT hill to goal

**Why not direct acceleration?**
- MountainCar has insufficient engine power
- Direct acceleration fails against gravity
- Momentum conversion is the optimal solution

## Technical Details

### Network Architecture
```
Input (2) -> Dense(64) -> ReLU -> Dense(64) -> ReLU -> Output (3)
```
- **Input**: Car position and velocity
- **Output**: Q-values for LEFT, NEUTRAL, RIGHT actions
- **Initialization**: Kaiming He initialization

### Training Algorithm
1. **Experience Replay**: Random sampling from buffer
2. **Target Network**: Stable Q-value targets
3. **Epsilon-Greedy**: Balanced exploration/exploitation
4. **Gradient Clipping**: Prevent gradient explosion

### Statistical Analysis
- **Confidence Intervals**: 95% CI using t-distribution
- **Degrees of Freedom**: n-1 (14 for 15 seeds)
- **Standard Error**: Standard deviation / sqrt(n)

## Troubleshooting

### Common Issues

1. **CUDA Out of Memory**
   - Solution: Set `FAST_MODE = True` or reduce batch size

2. **Slow Training**
   - Solution: Enable fast mode or use GPU

3. **Poor Performance**
   - Solution: Increase episodes or adjust learning rate

4. **Video Recording Fails**
   - Solution: Install `imageio-ffmpeg` package

### Performance Tips

1. **GPU Training**: Use CUDA-enabled GPU for 3-5x speedup
2. **Fast Mode**: Use for development and hyperparameter tuning
3. **Checkpointing**: Resume training from checkpoints if interrupted
4. **Monitoring**: Watch average returns for convergence
